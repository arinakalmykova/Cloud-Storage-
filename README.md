# PIXORY — облачный сервис хранения и оптимизации изображений

⚠️ **Проект находится в активной разработке**

PIXORY — это облачный сервис для загрузки, хранения, сжатия и управления изображениями. Проект разрабатывается в рамках ВКР и ориентирован на современную микросервисную архитектуру с использованием Docker, Kafka и REST API.

Сервис предоставляет личный кабинет пользователя, удобную работу с фотоархивами, интеллектуальный поиск и визуальное сравнение изображений до и после сжатия, а также рекомендации от искусственного интелекта.

---

## 🧩 Общая архитектура проекта

Проект состоит из двух основных частей:

* **Frontend** — пользовательский интерфейс (SPA)
* **Backend** — набор микросервисов, обменивающихся событиями через Kafka

Взаимодействие между сервисами реализовано по событийной модели (event-driven architecture).

## 🎨 Frontend

### Назначение

Frontend отвечает за пользовательский интерфейс, анимации и взаимодействие с backend API.

### Основной функционал

* Авторизация и регистрация пользователя
* Личный кабинет
* Загрузка изображений
* Выбор параметров сжатия
* Просмотр результата «до / после»
* Архив изображений (структура папок)
* Поиск по:

  * названию
  * дате
  * тегам
  * цвету
* Просмотр метаданных изображений


### Структура FSD

widgets/            - переиспользуемые UI-компоненты

### Планируемые фичи

* Красивая и плавная анимация интерфейса
* Drag & Drop загрузка
* Предпросмотр изображений
* UI-фильтры и сортировки

### Технологии (план / используется)

* JavaScript / TypeScript
* Современный SPA-фреймворк (React)
* REST API
* Figma (дизайн)

## ⚙️ Backend

Backend реализован в виде микросервисов, каждый из которых выполняет отдельную роль.

### Основные сервисы

#### 🔐 AuthService

* Регистрация и авторизация пользователей
* Генерация и валидация JWT-токенов
* Публикация событий в Kafka

#### 🖼 PhotoService

* Загрузка изображений
* Сжатие изображений
* Хранение метаданных
* Восстановление изображений (частично / по необходимости)
* Реакция на события из Kafka

#### 🗄 Storage

* Работа с файловым хранилищем
* Управление путями и структурой папок

#### MLService

* Обученная нейронная сеть на определение содержимого фото

## 📡 Kafka и события

В проекте используется **Apache Kafka** для асинхронного взаимодействия сервисов.

### Примеры событий

* `user_created`
* `photo_uploaded`
* `photo_processed`

Сообщения передаются в формате **JSON**.

Пример payload:

```json
{
  "event_type": "user_created",
  "event_data": {
    "userId": "uuid"
  }
}
```

Каждый сервис может:

* быть **producer** (отправлять события)
* быть **consumer** (подписываться на события)

## 🐳 Docker

Проект полностью контейнеризирован.

Используется:

* `docker-compose`
* отдельный контейнер на каждый сервис
* PostgreSQL для каждого сервиса при необходимости
* Kafka + Zookeeper

### Запуск проекта

```bash
docker compose up -d --build
```

⚠️ Перед запуском убедитесь, что у каждого сервиса существует файл `.env`.
